# Keck/OSIRIS in PypeIt: implementation plan

Date: 2026-10-10.  Authors: JXP and Claude (Fable 5.1).
Basis: `keck_osiris_design.md` (draft 2) and Q&A 1-25 in
`claude_prompts/keck_osiris/keck_osiris.md`.  One prompt per milestone
lives in `claude_prompts/keck_osiris/M1_*.md` to `M5_*.md`.  Branch: `osiris_port` (PypeIt) off
`develop`; dev-suite work on the matching branch.

Conventions for all code: Python, `pathlib`, `from pypeit import log`
and `PypeItError`, 80-character lines, imports at the top, numpy-style
docstrings describing inputs and outputs, and "Generated by JXP and
Claude" in the docstring of every new method.  New parameters go through
the `add-parameter` skill, new on-disk products through
`new-datacontainer`, the dev-suite entries through `add-devsuite-setup`,
and release notes through `update-changelog`.

Each stage ends at a **milestone** with a concrete, checkable acceptance
criterion and a report in `pypeitdev/keck_osiris/Reports/`.

## Stage 1 - Spectrograph skeleton: metadata, typing, raw reading

Goal: `pypeit_setup -s keck_osiris` works on all three raw directories
and produces correct frame types and configurations.

Tasks

1. `pypeit/spectrographs/keck_osiris.py`: `KeckOSIRISSpectrograph`
   with the attributes, `init_meta`, `compound_meta` (exptime unit
   logic, `instrument` fallback, `posang`, weather defaults with
   warnings), `configuration_keys`, `raw_header_cards`,
   `pypeit_file_keys`, `check_frame_type`, `get_detector_par` (read
   noise from `SAMPMODE`/`NUMREADS`), `get_rawimage` (DN conversion,
   era check, `VAR`/`DQ` carried on the HDU), `bpm` (DQ + static masks),
   `default_pypeit_par` (Section 4.8 of the design, without the new
   parameters yet).
2. Register the module in `pypeit/spectrographs/__init__.py`.
3. Static files: `pypeit/data/static_calibs/keck_osiris/` (hot and dead
   masks from OsirisDRP `data/`, gzipped) and
   `pypeit/data/spectrographs/keck_osiris/` (11 wavelength-coefficient
   files, the aluminium CTE table, epoch table from `calibrations.xml`,
   the slice-to-lenslet maps).
4. Unit tests `pypeit/tests/test_keck_osiris.py`: synthetic headers for
   2015, 2016-truncated, 2016-full and 2024 cards; exptime units;
   frame typing; era rejection; static-file loading.
5. Dev suite: add `keck_osiris` with setups `Hn3_100` and `Kbb_050` to
   `test_scripts/setups.py`; `.pypeit` files with `comb_id`/`bkg_id`
   filled by hand; `unit_tests/test_load_images.py` entry.

**Milestone M1**: `pypeit_setup` on `Hn3_100`, `Kbb_050` and `Kn5_035`
gives the expected types (science/sky/standard/dark/trace), one
configuration per directory, and the 2015 directory raises the
pre-2016 error at `run_pypeit`.  Report 03.

Estimated effort: 2-3 days.

**Status (2026-10-11): M1 done** (Report 03).  Changes that affect later
stages:

- `specflip = True` (the Keck wavelength runs right to left on the
  detector); the Stage 3 `rectify` step runs after `orient`, so the
  matrix (raw orientation) must be transposed *and* flipped.
- Standards are typed from the target name (`OBSTYPE` is `'a'` for all
  KOA frames); the A0V stars are `standard`, their `ISSKY=1` offsets
  `standard,sky`.
- `exptime = TRUITIME x COADDS` when `TRUITIME` is present (2024
  headers; seconds per coadd), else the `ITIME` rules.  The DN
  conversion and the metadata use the same value, so the 2-s
  standards are 1.475 s, the 600-s frames 598.963 s.
- `ISSKY=1` frames in the dev-suite pypeit files are typed `sky` only
  (backgrounds, not reduced on their own); document in Stage 5.
- New metadata keys `issky`, `sampmode`, `numreads`, `tmatemp` live in
  `pypeit/core/meta.py`; `tmatemp` (`DTMP7`) feeds the Stage 3
  wavelength step through `KeckOSIRISSpectrograph.grating_expansion`.
- Loaders for the wavelength coefficients (epoch selection), the CTE
  table and the Kbb slice/lenslet maps already exist on the class.

## Stage 2 - Rectification core and acceptance test

Goal: a numpy rectification that reproduces the DRP reference cube.

Tasks

1. `pypeit/core/lenslet_rectify.py`:
   - `RectMatrix` loader (`hilo`, `effective`, `influence`, header
     parameters; filename parser for filter/scale/date; selection of the
     latest matrix with date <= MJD from a directory).
   - Solver (a) `rectify_drp()`: faithful vectorised port of
     `spatrectif_000.c` (blame kernels, 15/10/5-iteration schedule,
     +/-64-slice coupling, 5-tap smoothing, 1.28 normalisation, output
     mask rule "> 4.5 of 9 weight on good pixels"), with the DRP's
     noise propagation.
   - Solver (c) `rectify_lstsq()`: batched per-band weighted
     least-squares (64 bands x 2048 columns of 32 x 19 systems) with
     ivar propagation and the same mask rule.
   - `narrowband_split()`: the `assembcube` rule mapping the 1216
     slices to lenslet (row, col) for narrowband filters (offsets 0,
     +16, +32 and the `sp > 831` remainder); broadband identity map.
   - `resample_to_drp_grid()`: evaluate the Keck wavelength solution
     and interpolate onto the DRP cube grid, for the comparison only.
2. New parameters (`add-parameter` skill) in `CalibrationsPar`:
   `osiris_rectmat_dir` (str, None), `osiris_rect_method`
   (`'drp'|'lstsq'`, default `'drp'` until (c) is validated),
   `osiris_rect_niter` (40), `osiris_rect_relax` (1.0),
   `osiris_rect_use_var` (bool, False).
3. Standalone script `pypeit_osiris_rectify` (`new-script` skill): raw
   (or A-B) frame + matrix -> rectified FITS (image, ivar, mask) for
   development and for the vet test; not part of the main flow.
4. Vet test `vet_tests/test_keck_osiris_rectify.py`: rectify
   `s160321_a002010 - s160321_a002011` with the Hn3/100 matrix,
   resample, compare with `s160321_a002010_Hn3_100_ref.fits` per spaxel.
5. Performance check: full frame in < 60 s for (a), < 10 s for (c).

**Milestone M2**: median absolute fractional difference to the DRP
reference cube < 2 % on spaxels with S/N > 10 and quasar-spaxel flux
within 5 %; solver (c) agrees with (a) to the same tolerance.  Report 04
with difference images and a per-lenslet comparison plot.

Estimated effort: 1-2 weeks (the schedule-faithful port is fiddly; the
least-squares solver is short).

**Status (2026-10-11): M2 done** (Report 04).  Changes that affect later
stages:

- Both solvers work on the raw orientation and return `(2048, nslice)`
  in the raw column order.  The M3 `rectify` step (after `orient`)
  un-orients the image (transpose + flip), solves, and flips the
  spectral axis of the output, rather than transforming the matrix.
- `lstsq` is an exact block-tridiagonal solve (adjacent lenslet-row
  bands are coupled; independent bands are wrong at band edges).
  Weighting by the Poisson noise lowers bright point sources by ~2 %
  (PSF-model error).  Decided (M2 Q&A 1): production `lstsq` uses
  flux-independent weights (read noise + smoothed sky variance) and the
  sandwich variance; `drp` stays the default until that exists (Stage 3
  task 8).
- DRP preprocessing reproduced in the Stage 3 `rectify` step (M2 Q&A 2,
  4): the per-column reference-row correction
  (`lenslet_rectify.subtract_reference_rows`) on every raw frame before
  A-B, and cosmic-ray flagging on the raw (A-B) frame (LACosmic,
  conservative; 2016-DRP strip rule as fallback) passed in the BPM.
- Variance (M2 Q&A 3): the rectified `ivar` always comes from the
  least-squares normal matrix, whichever solver produced the image; the
  DRP noise rule is kept in `rectify_drp` for fidelity only.
- Missing `DTMP7` (M2 Q&A 4): keep `grating_expansion(None) = 1` with a
  warning; never the DRP's 0 K extrapolation.
- Timing is not an issue: ~2 s per frame for either solver.

## Stage 3 - Rectification inside PypeIt and Fiber-pypeline calibrations

Goal: `run_pypeit` on `Hn3_100` produces spec1d files with one spectrum
per lenslet.

Tasks

1. `pypeit/images/rawimage.py`: new step `rectify` (after dark
   subtraction and BPM, before cosmic-ray masking) that runs only when
   `spectrograph.has_rectification` is True; it calls
   `spectrograph.rectify(image, ivar, bpm, hdr, par)` and replaces
   `image`, `rn2img`, `proc_var`, `datasec_img` and the BPM with their
   rectified counterparts.  `KeckOSIRISSpectrograph.rectify` loads and
   caches the matrix (by filter/scale/epoch) and dispatches to
   `lenslet_rectify`.  Inside the step (design 5.3, M2 Q&A 2-4):
   un-orient the image, subtract the reference rows
   (`subtract_reference_rows`), flag cosmic rays on the raw (A-B)
   frame into the BPM (LACosmic, conservative; DRP strip rule as
   fallback), solve, take the `ivar` from the least-squares normal
   matrix for either method, and flip the spectral axis of the result.
2. Fiber hooks in `keck_osiris.py`: `get_fiber_blocks`,
   `get_block_slit_edges` (fixed block boundaries),
   `identify_fibers_in_block`, `get_fiber_metadata`, `load_sky_layout`,
   `get_science_fiber_layout_indices`, `ifu_sky_wcs`, `get_wcs`,
   `get_datacube_bins`, with narrowband-aware lenslet mapping.
3. Identity tilts: new base-class hook `Spectrograph.get_fixed_tilts(slits)`
   returning a `WaveTilts` with zero tilt coefficients, used by
   `Calibrations.get_tilts` when defined (no tilt frame required).
4. Wavelengths from Keck coefficients: `keck_osiris.wavecalib_from_coeffs()`
   builds a `WaveCalib` (one `WaveFit` per block, polynomial
   lambda(pixel) from inverting the Keck relation with the
   grating-temperature term from `DTMP7`) and the per-lenslet shift
   table consumed by the Fiber pypeline's per-fiber shift machinery;
   a `Calibrations.get_wv_calib` path that uses a spectrograph-provided
   solution when `par['calibrations']['wavelengths']['method'] ==
   'fixed'` (new option, `add-parameter`).
5. Vacuum-wavelength flag in the spec1d header.
6. `FiberFindObjects`/`FiberExtract` on OSIRIS: verify the uniform
   profile fallback (no flat) and boxcar radius of one row; fix any
   assumption that fibers are several pixels wide.
7. Unit tests for the tilt hook, the wavelength inversion round trip and
   the block/lenslet mapping.
8. Production `lstsq` weighting (M2 Q&A 1): flux-independent weights
   (read noise + smoothed sky/background variance) with the sandwich
   variance `(A^T W A)^-1 A^T W V W A (A^T W A)^-1` (diagonal only);
   re-run the M2 vet test to confirm the quasar spaxel is within 1 % of
   `drp`.  `drp` remains the default until this passes.

**Milestone M3**: `run_pypeit` on `Hn3_100` completes; spec1d contains
~1000 lenslet spectra with `MASKDEF_ID` = lenslet id; the OH-line tilt
test (design Section 8, test 3) passes on the rectified sky frame;
collapsed-cube image of the quasar matches the DRP cube position.
Report 05.

Estimated effort: 2 weeks.

**Status (2026-10-11): M3 done** (Report 05), with the OH-line tilt
criterion open (Q&A 1 of `M3_pypeit_flow.md`; all seven M3 Q&A accepted
on 2026-10-12, design decisions M3-1 to M3-7).  Changes that affect later
stages:

- The rectified frame is re-laid out as a *lenslet image*: one spatial
  pixel per lenslet (`pos = 64 * block + slice % 64`, one block per Keck
  lenslet column present for the filter: 19 broadband, 51 narrowband).  The
  Hn3 spec1d holds 3040 spectra (one per lenslet), `MASKDEF_ID = row * 51 +
  col` of the Keck grid.  The fiber hooks need the filter/date, recorded on
  the spectrograph by `rectify` or `set_lenslet_state` (cube scripts must
  call the latter).
- Lenslets within a block are staggered by 1.92 px per lenslet row, so the
  per-lenslet "shifts" are full wavelength solutions
  (`get_fiber_wavelengths`, applied as offsets by the Fiber pypeline); the
  identity tilts make the spec2d wavelength image exact only for the block
  reference lenslets.  Stage 4 task 8 replaces them with Keck-derived
  fixed tilts (Q&A 2) before building 2D sky models.
- `osiris_rect_method` defaults to `lstsq` (flux-independent weights,
  sandwich variance; quasar within 0.03 % of `drp`).  Cosmic rays
  (L.A.Cosmic) and reference rows are handled per raw frame.
- With A-B pairs no fiber sky model is fit (`joint_fit = False`); Davies
  OH scaling (Stage 4 task 2) will plug in there.
- OH lines vs the Keck coefficients: 0.03-0.15 px trends across the blocks
  and a +0.4 A offset when the `DTMP7` term is applied (none without it);
  Stage 4 task 3 (OH refinement) closes the tilt criterion and task 9
  re-tests the `DTMP7` term on Kbb/050.
- Run time on Hn3/100: 2 min 45 s (13 s per rectified frame).

## Stage 4 - Science-mode run: sky subtraction, cube, telluric

Goal: a full reduction of the KOA Kbb/050 set (needs the Keck matrix).

Tasks

1. A-B / A-sky subtraction through `bkg_id` (already supported).  Dark
   policy (Q&A 23): no dark subtraction for frames that have a `bkg_id`;
   for unpaired frames use darks of the same ITIME (PypeIt does not
   rescale darks), selected through calibration groups.
2. Davies (2007) OH-scaled sky subtraction: new option in `SkySubPar`
   (`osiris_oh_scaling`), implemented in `pypeit/core/skysub.py` as a
   function that groups OH lines, fits per-group scale factors between
   the science and sky spectra (per lenslet or per block) and applies
   them before subtraction; used by `FiberFindObjects` when set.
3. OH wavelength refinement (`reference = 'sky'`, OSIRIS OH list in
   `pypeit/data/arc_lines/lists/`): per-lenslet zero-point correction
   (or a per-block linear term) with QA of the shift statistics.  Re-run
   the OH-line tilt test on the refined solution: this closes the open
   M3 criterion (slope < 0.05 px over a block; M3 Q&A 1).
4. Datacube (Q&A 24): new generic `pypeit_fiber_cube` script
   (`new-script` skill) built on `core/datacube.build_cube_from_spec1d`
   and the spectrograph's fiber hooks; `pypeit_binospec_ifu_cube` kept
   as a thin alias.  OSIRIS supplies the lenslet grid, `SSCALE` and the
   position-angle WCS through its hooks.  Compare the NGC 3245 cube with
   any DRP reduction available.
5. Telluric correction and flux calibration with the A0V standards using
   PypeIt's IR sensfunc/telluric tools; check the K-band grid choice.
6. Dev-suite: `keck_osiris/Kbb_050` reduce test, telluric test, and vet
   tests (cube structure, OH-line tilt test on an `ISSKY=1` frame).
7. (moved from Stage 3) Keck-derived fixed tilts: `get_fixed_tilts`
   returns a `WaveTilts` with a 2D Legendre per block that reproduces
   the 1.92 px per lenslet-row stagger (0.02-0.03 px rms); the
   per-lenslet `get_fiber_wavelengths` offsets keep only the residual,
   so the spec2d wavelength image is exact (M3 Q&A 2).  Do this before
   task 2 if the Davies scaling works on the 2D frame.
8. `DTMP7` re-test (M3 Q&A 4): measure the OH-line offset on the 2024
   Kbb/050 frames with and without the grating-temperature term; if it
   degrades them too, add a parameter to switch it off (or let the OH
   refinement absorb it) and record the decision.

**Milestone M4**: NGC 3245 reduced end to end; emission-line map and
continuum image look physical; sky residuals at OH lines reduced by the
scaling step; telluric-corrected A0V spectrum flat to a few percent; the
OH-line tilt test passes on the refined solution (closes M3).
Report 06.

Estimated effort: 2-3 weeks, gated on the matrix from Keck.

**Status (2026-10-12): M4 done** (Report 06; Q&A in `M4_science_mode.md`;
design decisions M4-1 to M4-9).  Changes that affect Stage 5:

- Matrix selection is by Keck validity epoch (`rectmat_epochs.ecsv`, task
  11); the user documentation must explain the tkserver listing.
- Tilts are Keck-derived (Stage 4 task 7, M4 task 8); broadband lenslet windows are the filter
  band (out-of-band pixels masked).
- Per-lenslet OH zero points on every science frame (`fiber_sky_refine`),
  the `DTMP7` term off by default (`osiris_grating_temp`), Davies OH
  scaling (`osiris_oh_scaling = global`) on A-B frames.
- Darks are processed unrectified so they can be subtracted from unpaired
  frames; the dev-suite file keeps them in ITIME calibration groups 1-3, and
  only one A/B pair carries the `arc,tilt,trace` types (the fixed
  calibrations need one frame; combining 23 rectified frames cost ~15 min).
- `pypeit_fiber_cube` (generic, with `--point_source`) replaces the
  Binospec cube script (now an alias); telluric correction runs on the
  point-source spec1d of the A0V star (`pypeit_sensfunc`, `pypeit_tellfit
  --objmodel star`, response polynomial order 7), frame
  `OS.20240203.59407.32` (the 8.85-s frames 56998/57040 hold no star).
- Dev suite: `keck_osiris/Kbb_050` reduce, fiber-cube (`PypeItFiberCubeTest`,
  new test type), sensfunc and telluric tests; vet tests
  `test_keck_osiris_flow.py` (tilt test on Hn3 and Kbb, no `xfail`) and
  `test_keck_osiris_kbb.py` (spec1d, cube, telluric flatness).
- Carried into Stage 5 (Q&A 2-7 of M4, accepted 2026-10-13; design
  decisions M4-10 to M4-13): the Davies-scaling guard for short frames
  (task 6), the line-map step diagnosis (task 7), the science-frame-as-arc
  OH fallback for very short frames (task 8), residual cosmic rays that
  L.A.Cosmic misses on single raw frames and the per-frame recomputation
  of `get_fixed_tilts` (task 9); the shared-code changes of Report 06 are
  flagged for the reviewers in task 5.

## Stage 5 - Hardening, documentation, release

Tasks

1. Narrowband and other scales: run on at least one more mode from KOA
   (Kn3/035 or /050) once its matrix is available; fix mapping edge
   cases (filters with fewer complete lenslets).
2. Header-era and truncated-header robustness tests; clear user-facing
   errors for a missing matrix (list what was found in the directory).
3. Documentation: `doc/spectrographs/keck_osiris.rst` (data
   requirements, how to obtain matrices, the `bkg_id` convention, the
   parameters), link from `spectrographs.rst`, a tutorial, release note
   in `doc/releases/2.1.0dev.rst` (`update-changelog` skill), rebuilt
   parameter and datamodel docs (`build-docs` skill).
4. Set `supported = True`; copy the raw data (all 73 Kbb/050 frames
   for now, to be trimmed later per Q&A 25) and the pypeit files to the
   dev-suite Google Drive.
5. Pull request to `develop` with the dev-suite PR cross-referenced;
   credit the OSIRIS DRP authors.  Flag for the reviewers the generic
   shared-code changes of M3: the `runtime_par` mechanism
   (`Spectrograph.set_runtime_par`, set by `PypeIt.__init__`) and the
   column-window boxcar speed-up in `FiberExtract` (M3 Q&A 7), and the
   M4 ones listed in Report 06 section 2 (M4 Q&A 7).
6. Davies-scaling guard (M4-10): judge each group factor on the
   integrated line residual (Report 06, 5.3) and/or skip the scaling
   below a minimum sky-line S/N (e.g. `EXPTIME < 100 s`, parameter);
   the 44-s NGC 3245 frames must no longer get worse; `global` stays the
   default.
7. Line-map step (M4-11): map the raw detector column of H2 1-0 S(1) and
   Br gamma (and their side bands) per lenslet, test the column-1024 /
   readout-channel hypothesis, compare with a DRP reduction of one frame
   if IDL is available, and fix or document the cause.
8. OH refinement for very short frames (M4-12): when a frame yields no
   measurable sky line, use a science frame of the same night and
   configuration as the arc (apply its per-lenslet shifts; fallback the
   night median) with a warning; the 1.5-s HD89239 frames must end up
   within ~0.1 px of the refined science frames.
9. Performance and robustness: cache `get_fixed_tilts` per configuration
   (168 recomputations in the Kbb run); a second cosmic-ray pass on the
   rectified A-B frame or frame-combination rejection for the residual
   hits L.A.Cosmic misses on single raw frames.

**Milestone M5**: dev-suite `reduce`, `afterburn` and `vet` pass for
both OSIRIS setups; docs build clean; PR opened.

Estimated effort: 1 week.

## Dependencies and risks

| Risk | Mitigation |
|---|---|
| Keck matrix for Kbb/050 delayed | Stages 1-3 proceed on Hn3/100; the request also asks for stable hosting |
| DRP schedule port does not reach 2 % agreement | fall back to comparing solver (c) against the DRP within a looser tolerance and treat the DRP's smoothing as the difference; document it |
| `RawImage` step touches shared code | keep the step generic (`has_rectification`), default off, covered by existing tests |
| Fiber pypeline assumes multi-pixel fibers | identify and parametrise the assumptions in Stage 3 task 6 |
| 1216 lenslets x 2048 pixels per frame is heavy for extraction/QA | one slit per block keeps calibrations small; boxcar extraction is O(N) |
