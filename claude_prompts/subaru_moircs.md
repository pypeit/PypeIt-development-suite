**Mosaic (your answer to Q8)**

17. The two chips are not neighbours on one focal plane.  MOIRCS splits
    the beam into two channels, each with its own camera and grism, and
    the field is split along the *dispersion* direction (x; the headers
    give `DET-P101 = -90"` and `DET-P102 = +90"`).  So a "mosaic" here
    can't be a physical one.  It would be a virtual image with chip 2
    stacked above chip 1 in the spatial direction (plus a gap), built
    with PypeIt's `Mosaic` machinery using shifts and flips only.  Two
    options:
    - **(a) `ndet = 2`, no mosaic.**  One run reduces both chips.  The
      outputs hold DET01 and DET02 in the *same* spec2d/spec1d file per
      exposure, as for DEIMOS reduced without a mosaic.  Calibrations
      such as edges, tilts, and wavelengths stay per chip, where they
      are physically meaningful.
    - **(b) `ndet = 2` plus an allowed mosaic `(1,2)`**, giving one
      MSC01 image.  The catch: slit-edge PCA and syncing would run
      across two optically independent channels, and the edge traces
      might fit worse.

    Both need the same groundwork, so I propose doing (a) first and
    adding (b) as an option once (a) works.  Downstream, (a) already
    gives you one file per exposure.  Is that OK, or do you need the
    single mosaic image specifically?
    >A: Agreed, do (a) first
18. To do either option, the chip-1 file becomes the frame listed in
    the PypeIt file.  The spectrograph's `get_rawimage` would then open
    the chip-2 companion itself.  Its file number is the chip-1 number
    plus 1, and it is checked by requiring the same `EXP-ID` and
    `DET-ID = 2` (true for all 9 pairs here).  Chip-2 files would be
    left out of `pypeit_setup`'s table.  Two sub-questions:

      is missing?
    - Should a user still be able to reduce chip 2 alone (e.g. if chip 1

    >A: Yes, raise an error if a companion file is missing.  And, yes, a user should be able to reduce chip 2 alone if chip 1 is bad.
