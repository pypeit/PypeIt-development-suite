### Planning

##### 2026-06-15 — Plan for science-frame state monitoring

**What I did.** Ran all three `pypeit_reduce_by_step` stages on
`shane_kast_blue_A` frame `b27` (DET01) in the dev suite
(`REDUX_OUT/shane_kast_blue/600_4310_d55/shane_kast_blue_A`) and inspected the
intermediate + final products to learn what state/metrics are available where.

**The science reduction structure (vs. calibrations).** Unlike calibrations —
one `Calibrations.run_the_steps` loop that already threads `run_state` — science
reduction is spread across `pypeit/exposure.py` and `pypeit/pypeit_steps.py`.
`exposure.reduce_exposure(frames, calib_ID, run_state, ...)` (already *receives*
`run_state` but does **not** update it for science) drives, per **detector**,
three macro-steps that match `pypeit_reduce_by_step`'s `process|findobj|extract`:
1. `process_exposure` → `process_one_det` → processed `sciImg` (bias/flat/etc.)
2. `findobj_on_exposure` → `findobj_on_det` + `finalize_sky_det` → detected
   objects + initial/final sky
3. `extract_exposure` → `extract_det` → `spec2d` + `spec1d`; then
   `exposure.save_exposure` writes the final products.
The unit of work is a **reduced exposure** = a `comb_id` (one or more combined
raw frames, identified by `basename`, e.g. `b27-J1217p3905_KASTb_<UTC>`) × a
**detector/mosaic**. Standards are reduced first (as a tracing crutch), then
science; both should be tracked (`objtype`).

**The intermediate-files caveat (key challenge).** The *standard* `run_pypeit`
writes **no** intermediate files — `sciImg`/`Sky`/`slits`/`spec1d(_all)` only
appear under `Intermediate/` when run via `pypeit_reduce_by_step`. So the
Dashboard cannot rely on intermediates. State must come from **two** sources
(mirroring the calibration design):
- *Live*: `run_state` hooks updated **in-memory during the run**, at the
  `reduce_exposure` orchestration level (after each of the 3 stages, using the
  returned `sciImg_dict` / `all_specobjs_find` / `all_spec2d` dicts), written via
  the existing `safe_write`/`safe_update_*` path.
- *Derive* (no state file, à la `pypeit_status`): reconstruct science state from
  the **final on-disk products** — `spec1d_*.fits` (per-object metrics) and
  `spec2d_*.fits` (per-detector/slit, flexure, sky) — since those are all that a
  normal run leaves behind.

**What metrics live where (grounded on the b27 run).**
- *findobj* (intermediate `spec1d_*_all.fits`, in-memory `sobjs`): per object
  `OBJID`, `SLITID`, `DET`, `SPAT_PIXPOS`, `FWHM`, `smash_snr` (b27: 1 object on
  slit 175, **smash_snr=142.5**, matching the workflow doc's "SNR≈142"); total
  `nobj`; per-slit object count; `reduce_bpm` → slits flagged **`BADSKYSUB`**;
  global spectral-flexure shift.
- *extract* (final `spec1d_*.fits` `SpecObj`): per object `S2N` (extraction S/N),
  `OPT_CHI2`, `OPT_FRAC_USE`, `OPT_COUNTS`/`BOX_COUNTS` (availability),
  `WAVE_RMS`, `FLEX_SHIFT_TOTAL`, `sign` (neg traces); per-slit **`BADEXTRACT`**;
  products `spec2d`/`spec1d` paths. (The slit bitmask already carries
  `BADSKYSUB` and `BADEXTRACT`, parallel to the calib `BAD*CALIB` flags.)
- *process*: little intrinsic metric; mainly status + (when present) the
  intermediate `sciImg` path. Could record basic image stats later.

**Proposed data model (`state.py`).** A new `science` list on `RunPypeItState`,
**one entry per (frame/basename, det)** carrying the three macro-step statuses
plus products and per-slit/per-object detail — this maps directly to the
Dashboard's per-frame Science rows (R18) rather than the per-step calib layout:

```
class ScienceObj(BaseModel):          # one detected/extracted object
    objid: int
    slitid: Optional[int] = None
    spat_pixpos: Optional[float] = None
    fwhm: Optional[float] = None
    snr_find: Optional[float] = None   # smash_snr (findobj)
    s2n: Optional[float] = None        # extraction S/N (extract)
    wave_rms: Optional[float] = None
    flex_shift: Optional[float] = None
    extracted: bool = False

class ScienceSlit(BaseModel):          # per-slit science status
    status: Literal["success","fail","skip","undone"] = "undone"
    nobj: Optional[int] = None         # objects found on this slit

class ScienceStep(BaseModel):          # process/findobj/skysub/extract
    status: Literal["undone","running","success","fail"] = "undone"

class ScienceFrameState(BaseModel):    # one reduced exposure × detector
    frame: str                         # raw filename or combined basename
    det: int | List[int]
    calib_id: int
    objtype: str                       # 'science' | 'standard'
    comb_id: Optional[int] = None
    process: ScienceStep = ScienceStep()
    findobj: ScienceStep = ScienceStep()
    skysub:  ScienceStep = ScienceStep()   # final global sky (Q1)
    extract: ScienceStep = ScienceStep()
    spec2d_file: Optional[str] = None
    spec1d_file: Optional[str] = None
    nobj: Optional[int] = None
    spec_flexure: Optional[float] = None
    spat_flexure: Optional[float] = None
    slits: Optional[Dict[int, ScienceSlit]] = Field(default_factory=dict)
    objects: Optional[List[ScienceObj]] = Field(default_factory=list)

# on RunPypeItState:
    science: Optional[List[ScienceFrameState]] = Field(default_factory=list)
```

**Proposed code changes.**
1. `state.py`: add the classes above + `science` field; a `safe_update_science`
   helper (mirroring `safe_update_calib`) keyed by `(frame, det)` using the
   `same_det` matcher; extend `get_status()`/`print_status()`/the summary to
   include a science table (and keep the calibration table unchanged).
2. `exposure.py` (`reduce_exposure`): after each of the 3 stages, mark the
   step `running`→`success`/`fail` per `(frame, det)` and record metrics from the
   returned dicts (`sciImg_dict`, `all_specobjs_find`, `all_spec2d`), all via the
   `safe_*` wrappers so it can never crash a run. Set product paths after
   `save_exposure`.
3. A derive path (extend `pypeit_status` or add a sibling) that builds the
   science state from on-disk `spec1d`/`spec2d` when no `*_state.json` exists.

**Dashboard payoff (R7/R15/R18).** A Science section with one row per
science/standard frame, glyph-coded process/findobj/extract status, `nobj`, and
`spec2d`/`spec1d` presence (filterable/scrollable for MOS); a per-frame detail
view with per-slit (nobj, BADSKYSUB/BADEXTRACT) and per-object (SNR, FWHM, S2N,
flexure, WAVE_RMS) tables — exactly the at-a-glance signals the workflow doc's
`obj_prof`/`obj_trace` QA convey; and a whole-run summary that now spans
calibrations **and** science.

**Open challenges to settle in Q&A.** Modeling granularity (per-frame vs
per-step), keying (raw frame vs combined basename), how much per-object detail to
store for crowded MOS slits, where exactly to hook (orchestration vs per-det
functions), whether the derive path is in scope for v1, and the success/empty
semantics (0 objects on blank sky is not a failure).

##### 2026-06-15 — Revision after Q&A round 1

All eight questions answered; decisions now locked. Changes to the plan above:

**Locked.** One per-frame `ScienceFrameState` entry per `(frame, det)`; key by
combined `basename` + store contributing raw `frame`(s)/`comb_id`; track both
science and standard (`objtype`); **store all** detected objects (small field
set); live hooks **inside `exposure.reduce_exposure`** (confirmed — at the
orchestration level, not the per-det `pypeit_steps` functions); the derive path
**is in v1**; v1 metric set as proposed; `success` if a step ran without error
(record `nobj=0`), `fail` only on exception or per-slit `BADSKYSUB`/`BADEXTRACT`;
record `comb_id`/`bkg_id` + object `sign` for A-B but otherwise treat normally.

**New: add a `skysub` step (per Q1).** The macro-steps become **four** —
`process → findobj → skysub → extract`:
- `process`  = `process_one_det` (processed `sciImg`)
- `findobj`  = `findobj_on_det` (object detection + *initial* sky)
- `skysub`   = `finalize_sky_det` (final global sky model)
- `extract`  = `extract_det` (→ `spec2d`/`spec1d`)
`findobj_on_exposure` runs both `findobj_on_det` and `finalize_sky_det`
internally, so in `reduce_exposure` the `findobj` and `skysub` statuses are
recorded together when that stage returns (per-slit `BADSKYSUB` carries the
sky-quality detail). `ScienceFrameState` now carries a `skysub: ScienceStep`
(see the updated model above).

**New (per Task 2): derive state from files, with a priority order.** The derive
path (used when there is no `*_state.json`, e.g. on Dashboard launch) builds each
`(frame, det)`'s state from disk, **giving priority to the final Science
products** and falling back to `Intermediate/` files for in-progress
`reduce_by_step` work:

  1. **Science products (authoritative):**
     - `Science/spec2d_<basename>.fits` present → `process`, `findobj`, `skysub`
       all `success`; read per-detector slits (per-slit `BADSKYSUB`/`BADEXTRACT`)
       and flexure.
     - `Science/spec1d_<basename>.fits` present → `extract = success`; read the
       per-object metrics (`S2N`, `SPAT_PIXPOS`, `FWHM`, `smash_snr`, …) and set
       `spec1d_file`/`spec2d_file`.
     If both exist, the frame is fully reduced; the per-object/per-slit detail is
     taken from these.
  2. **Intermediate files (fallback, only to fill steps the Science products do
     not yet cover):** map file → furthest-completed step:
     - `Intermediate/sciImg_<basename>_<det>.fits` → `process = success`
     - `Intermediate/spec1d_<basename>_all.fits` → `findobj = success`
       (objects found; read `smash_snr`/`SPAT_PIXPOS`/`FWHM`, `extracted=False`)
     - `Intermediate/Sky_<basename>_<det>.fits` → `skysub = success`
     - (extract has no distinct intermediate; the final `Science/spec1d` is its
       product)
     Intermediate detail is used **only** for steps not already satisfied by the
     Science products (Science always wins on conflict).
  3. Nothing on disk → all steps `undone`.

  This makes the Dashboard show real progress both during a normal run (via the
  live `*_state.json`) and during/after a partial `reduce_by_step` session (via
  Intermediate files), while always preferring the authoritative Science
  products. The normal `run_pypeit` path is unchanged — it still writes no
  Intermediate files; only `reduce_by_step` does.

**Dashboard status columns** accordingly become `process | findobj | skysub |
extract` per science row.
