**1. Pypeline / extraction strategy (the big one).**  OSIRIS is a *lenslet*
IFU, not a slicer.  The lenslet grid is rotated 3.6 deg (tan = 1/16) to the
dispersion axis, so on the 2048x2048 raw frame adjacent lenslet spectra are
only **2 px apart vertically** (staggered ~32 px horizontally, 16 spectra
per 32-px band, 64 bands = 2048 rows), each with a ~2 px FWHM spatial PSF.
1216 spectra (broadband) or up to 3072 (narrowband, packed 3 head-to-tail
along the 2048-px row) overlap heavily.  OsirisDRP does not trace/extract;
it does a 40-iteration PSF-deconvolution ("Spatially Rectify") against a
Keck-supplied rectification matrix (`*_infl_<filt>_<scale>.fits`:
ext2 = [1216,16,2048] lenslet PSF cube, ext0 = (x,y) per lenslet,
ext1 = row index).  PypeIt's slit-edge tracing and the Fiber block-slit
model (Binospec fibers are well separated) cannot resolve 2-px-spaced
spectra.  Which of these do you want?

   a. **Port the rectification step.**  Implement the OsirisDRP iterative
      extraction (`spatrectif_000.c`) in numpy, using Keck's rectification
      matrices as a calibration input.  PypeIt then takes over at the
      "rectified" stage: a 1216x2048 image of straight, one-row-per-lenslet
      spectra, which maps naturally onto the Fiber pypeline (one object per
      lenslet, lenslet IDs from `get_fiber_metadata`), followed by
      wavelength calibration and PypeIt's coadd3d/datacube machinery.
      *My recommendation* - it reuses the only proven OSIRIS extraction
      and most of PypeIt.
   b. **PypeIt-native tracing/extraction** of the interleaved spectra
      (needs Keck's per-lenslet-column white-light scans, which observers
      never take; large new algorithmic work).
   c. Something hybrid you have in mind.

   Note: `pypeline` must be `MultiSlit`, `Echelle`, `SlicerIFU` or `Fiber`.
   KCWI is `SlicerIFU`; option (a) suggests `Fiber`.  Confirm?

   *Recommendation: (a), with `pypeline = 'Fiber'`.*  Why: the 2-px
   spacing of neighbouring lenslet spectra is below what any
   edge-tracing or profile-separation scheme in PypeIt can resolve, so a
   forward model of every lenslet PSF is unavoidable.  Keck already
   measures and maintains exactly that model (the rectification matrix)
   for every filter/scale/epoch, and the DRP's iterative solver has 15+
   years of validation.  Porting `spatrectif_000.c` (a Gauss-Seidel style
   iterative least-squares, ~300 lines of C) to numpy/scipy.sparse is a
   bounded task, and its output, a 1216x2048 image of straight spectra,
   is precisely the input the Fiber pypeline was built for: each lenslet
   IS the object, no object finding, lenslet IDs via
   `get_fiber_metadata`, then PypeIt's wavecal, sky subtraction and
   coadd3d.  Option (b) would need calibration scans only Keck can take
   and would re-derive the same PSF model with less data.  Plan the port
   as a pre-processing step that runs inside `get_rawimage` (or a new
   `RawImage` hook) so everything downstream sees a rectified frame.

>A. Ok, we will go with your Recommendation.

**4. Raw file format / units.**  Raw frames are up-the-ramp outputs in
   **DN/s** with three extensions: ext0 signal (DN/s), ext1 noise, ext2
   byte quality map (9 = good, 0 = bad; Keck's bad-pixel mask is applied
   there by `apply_mask.py`).  Preferences on:
   - `get_rawimage`: multiply by TRUITIME x COADDS to return DN so
     PypeIt's gain/RN noise model is meaningful, or keep DN/s and set
     gain/RN accordingly?
   - Use ext2 (and OsirisDRP's `badpixelmask20170902_sigma50.fits.gz` /
     `bpm_dead_4pixbufgood.fits.gz`) as the PypeIt BPM?

   *Recommendation: convert to DN in `get_rawimage` (multiply by
   TRUITIME x COADDS, set exptime to the same product) and build the BPM
   from ext2 == 0 OR the Keck 50-sigma hot mask OR the dead mask.*  Why:
   PypeIt's variance model is Poisson(DN x gain) + RN^2; feeding DN/s
   would understate the shot noise by the integration time unless we
   also rescale gain/RN per frame, which is fragile.  Converting keeps
   gain = 2.15 e-/ADU and RN selectable from SAMPMODE/NUMREADS honest.
   Ext1 (the server's own noise estimate) should not be discarded: carry
   it as an optional weight for the rectification solver, where the DRP
   uses it.  The Keck masks are ~100 kB gzipped and belong in
   `pypeit/data/static_calibs/keck_osiris/`.

**6. Wavelength calibration.**  Keck supplies date-dependent global
   wavelength polynomial coefficients per lenslet
   (`data/osiris_wave_coeffs_*.fits`, 11 epochs) that the DRP applies
   with a grating-temperature correction; there is also an OH line list
   (`ohlines_kbb_all.dat`) and an arc list (`osiris_cal_line.list`,
   Ne/Ar/Xe/Kr).  Options: (i) adopt the DRP coefficients directly as the
   PypeIt wavelength solution; (ii) fit OH sky lines in each rectified
   lenslet spectrum with PypeIt's `full_template`; (iii) both (DRP as
   first guess, OH refinement).  Preference?  Wavelengths are vacuum.

   *Recommendation: (iii).*  Why: the Keck per-lenslet polynomial
   coefficients are accurate to ~0.1 px but carry documented offsets of
   0.3-0.6 A that depend on scale and epoch (Table 4-1, Fig. 4-4) because
   arc lamps do not fill the pupil the way the sky does; OH lines do.  So
   use the epoch-matched DRP coefficients to build a per-lenslet template
   (a `reid_arxiv`-style archive, no line identification needed) and let
   PypeIt refine the zero point and low-order terms against the OH list
   in the science/sky frames.  Where there are no OH lines (long end of
   K, narrowband filters with <3 lines) fall back to the DRP solution
   alone.  Store everything in vacuum, as the DRP does.

>A. Use your Recommendation
