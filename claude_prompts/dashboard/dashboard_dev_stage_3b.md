# Stage 3b of the PypeIt Dashboard — Test on keck_nires (Echelle)

## Goals

Before proceeding to Stage 4, we should exercise the Dashboard — built and
documented through Stage 3 (Status view + Calibrations view + status/activity
area) — on an **echelle** spectrograph.  All testing so far has been on the
**MultiSlit** path (`shane_kast_blue` single-slit, `keck_lris_blue` multi-slit /
multi-detector).  This document guides a **test-only** pass on **`keck_nires`**,
a fixed-format near-IR echelle, to confirm the dashboard's path-awareness and
per-**order** behavior before new features are added.

This is a **verification** stage: the goal is to find issues, not build new
views.  Small UI fixes that the test surfaces (e.g. labeling) are in scope; the
(re)generate control and run-lock/clobber remain **Stage 4**.

Stage 3b builds on everything from Stages 0–3 (the `DashboardModel`, the
palette, the Status and Calibrations views, the inspection launcher, the
status/activity area).

**Goal.** Confirm the Status and Calibrations views are correct and legible on a
fixed-format echelle, and that "orders" are presented sensibly (the dashboard's

**What to test.**

   re-scope correctly across groups.

   labels should read **"Order"** for the Echelle pipeline (see S3b-Q1).

   per-order ``Arc_1dfit`` figures appear where expected (see S3b-Q2).  There should
   also be ``Arc_2dfit_global_qa`` and ``Arc_2dfit_orders_qa`` figures.
6. **Render matrix.** Extend the layout-check harness to render the
   `keck_nires` Status and Calibrations views (light/dark) for the milestone
   screenshots.

**Acceptance criteria.**

- The `keck_nires` reduction loads and both views render without error, light
  and dark.
- The navigator and scope drop-downs handle the multiple calibration groups;
  switching groups re-scopes correctly.
- The per-order drill-down shows one row per order with the right status +
  metric (and is labeled appropriately — S3b-Q1).
- Inspection tools launch for the echelle calibrations.
- Any echelle-specific issues are logged; fixes (if small/in-scope) are applied
  and re-verified, else recorded for a later round.
