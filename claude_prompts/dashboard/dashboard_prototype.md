**Goal.** Performed the first Prep task: launch the existing dashboard, examine

**Commands used.**

  dashboard.rst}` and the entry point
  `pypeit/scripts/pypeit_dashboard.py` (registered in `pyproject.toml` as


  `DISPLAY=:0 import -window 0x7600007 dash_window.png`

**UI assessment (window renders correctly).** Two-panel layout:

- *Left column* — six action buttons stacked vertically: **Open Setup**,
  **Import Setup**, **Run All**, **Run Next**, **Help**, **Check Status**
  (themed icons + left-aligned text).
- *Top-right* — a 6-field status bar: Setup File, Calibration ID, Detector,
  Science File, Step, Calibration Step (all read "None" at startup).
- *Bottom-right* — a tab widget: **Status** (empty `QTableWidget`), **QA**,
  **Calibrations**, **Science** (file-tree views), **Logs** (read-only text).

**Current-state findings (what works / what is broken).**

1. **Entry point not installed in `pypeit14`.** `pypeit_dashboard` is absent
   from `PATH`; the editable install predates the `pyproject.toml` entry point.
   Had to invoke `RunDashboard.entry_point()` directly. A `pip install -e .`
   refresh would fix this.
2. **Undeclared runtime dependencies.** The dashboard fails to import until
   `pandas` (imported at top of `dashboard.py`) and `pydantic` (imported by
   `pypeit/state.py`, pulled in via `pypeit_worker`) are installed. Neither is
   listed in `pyproject.toml`. I `pip install`ed both into `pypeit14` to launch.
   These must be added as declared dependencies.
3. **`parse_pypeit_setup_file()` hangs (infinite loop) on real files — Import
   Setup is effectively broken.** The spectrograph regex is
   `r"^\s*spectrograph\s*=\s*(\s+)"`, which captures *whitespace* `(\s+)` after
   the `=` instead of the value. On a modern `.pypeit` file
   (`spectrograph = shane_kast_blue`) it never matches, and the
   `while spectrograph is None: setup.readline()` loop spins forever once EOF is
   reached (`readline()` keeps returning `""`). Verified: parsing
   `shane_kast_blue_452_3306_d57.pypeit` never returns and had to be killed.
   Fix: capture `(\S+)` and guard the read loops against EOF. The `path` and
   file-table regexes look serviceable but are untested downstream because the
   function never reaches them.
4. **No setup loaded ⇒ Check Status / Run All inert.** Because Import hangs,
   `self.setup_file_path` is never set, so **Check Status** (already noted in
   `dashboard.rst` Known Issues) and **Run All** have nothing to act on.
5. **Stubs.** **Run Next** and **Help** are wired to no handlers (confirmed in
   `dashboard.rst`). Debug `print()` calls remain in `import_setup_file` and
   `pypeit_worker.PypeItWorker`.
6. **Portability.** File-tree paths are hard-coded with `/` (Windows-broken),
   as the docs note.

**Recommendations for the next stage of development.**

- *Highest priority:* fix the spectrograph regex (`(\s+)` → `(\S+)`) and add
  EOF guards in `parse_pypeit_setup_file()` so Import Setup stops hanging; add a
  unit test in `pypeit/tests/` that parses a sample `.pypeit` file.
- Declare `pandas` and `pydantic` in `pyproject.toml`; reinstall so the
  `pypeit_dashboard` entry point lands on `PATH`.
- End-to-end smoke test: Import → Check Status → Run All against
  `shane_kast_blue/600_4310_d55` to validate the live log streaming and the
  `QFileSystemWatcher` directory auto-discovery.
- Implement (or hide) the **Run Next** and **Help** stubs; remove debug
  `print()`s and route them to the Logs tab.
- Wire the status-bar fields (Calibration ID, Detector, Step, …) to the
  `STEP`-level log signal that `QtLogHandler` already emits but nothing yet
  consumes.

**Goal.** Performed task 1 under Skills: search the web for any Claude (Agent)

**Method.** Two `WebSearch` queries ("Claude Agent Skill PyQt6 qtpy GUI

**Headline:** there is no Claude skill specifically for **qtpy** — every result
assumes direct `PyQt6`/`PySide6` imports. The dashboard uses qtpy as a
backend-agnostic shim, so any code these skills generate would need to be
re-routed through `qtpy.*` imports to match house style. That said, several
PyQt6 skills carry directly-relevant best-practice patterns.

**Skills found, ranked by relevance to our dashboard.**

1. **`pyqt-expert`** (lobehub, `diferansiyel1/qorsense_desktop`) — *most
   relevant.* Building high-performance cross-platform desktop apps with PyQt6
   **and PySide6**: native UI aesthetics, custom widget creation, the Qt
   **model–view architecture** for scalable data handling, and correct
   **multithreading** (`QThread`, signals/slots, `moveToThread`) to avoid UI
   freezes; also system integration (files, tray, OS APIs), custom painting,
   and event-loop optimization. The model–view guidance maps onto our
   `status_table_widget`, which currently rebuilds the whole `QTableWidget` on
   every refresh instead of using a `QAbstractTableModel`.

2. **`pyqt6-ui-development-rules`** (GitHub `oimiragieo/agent-studio`, indexed on
   explainx.ai) — a rules/lint-style skill enforcing five "iron laws":
   signal/slot MVC separation, never block the main UI thread, centralized QSS
   theming at the `QApplication` level, layout-manager-driven (DPI-aware)
   layouts instead of absolute coordinates, and cross-platform testing
   (Win/macOS/Linux). Ships a `WorkerThread(QThread)` pattern emitting
   `progress`/`finished_with_result`/`error` signals, and mentions
   `asyncio + qasync` as an alternative. **Does not mention qtpy.** Install:
   `npx skills add https://github.com/oimiragieo/agent-studio --skill
   pyqt6-ui-development-rules` (supports Claude Code, Cursor, Cline). Directly
   useful as a checklist: our hard-coded `/` paths and per-widget
   `value_style_sheet` styling violate laws 4 and 3; our background
   `multiprocessing` worker + `QtLogHandler` signals already satisfy law 2.

3. **The Qt Company official `agent-skills`** (`TheQtCompanyRnD/agent-skills`,
   also on Anthropic's plugin marketplace as `qt-development-skills`) — 12
   skills (qt-cpp-review, qt-qml-review, qt-qml/qt-cpp-docs, qt-qml-test(+run),
   qt-qml-profiler, qt-ui-design, qt-figma-*). **QML/C++ only — no Python /
   PyQt6 / PySide6 / qtpy support**, so not directly usable for this dashboard.
   The one transferable piece is `qt-ui-design` (a general Qt UI/UX audit) whose
   layout/affordance principles apply regardless of binding. Install:
   `/plugin marketplace add TheQtCompanyRnD/agent-skills` then
   `/plugin install qt-development-skills`, or symlink individual skills into
   `~/.claude/skills/`.

**General marketplaces** for discovering more (no qtpy-specific entries seen):

**Changes made (files):**

1. **`pypeit/dashboard/dashboard.py` — `parse_pypeit_setup_file()` rewritten.**

   whitespace after `=`) instead of `(\S+)` (the value), so it never matched
   and the unbounded `while ...: readline()` spun forever at EOF. Now a single
   bounded pass over the file with `(\S+)` for the spectrograph and explicit
   EOF termination — a missing keyword returns `None` instead of hanging. Also
   broadened the data-row regex to accept gzipped frames

   `parse_step_message()` (a pure, unit-testable helper that splits the

   `MainWindow.update_status_from_step()` (routes `calib_id`/`det`/
   `calib_step`/`meta_step` to the existing `StatusWidget.update_*` setters).
   Connected `qt_handler.step_signal` → that slot in `main()` (previously
   `step_signal` was emitted but never connected to anything).

3. **`pypeit/pkg/logger.py` — custom `STEP` log level.** Registered
   `STEP = 15` (named "STEP") and added `PypeItLogger.step()`. The level sits

   to DEBUG and attaches a `QueueHandler`, so STEP records propagate across the

4. **`pypeit/state.py` — emit STEP on transition.** `RunPypeItState`
   gained `_broadcast_step()`, called from `update_calib()` **only when the
   step actually changes** (so the repeated metric/status updates that follow
   don't spam the log). Payload:
   `calib_id=…|det=…|calib_step=…|meta_step=Calibrations`.

5. **`pyproject.toml`** — declared `pandas>=1.5` and `pydantic>=2.0` as

### How to launch and use the dashboard

**Once-off:** make sure the GUI deps and entry point are installed in your
environment (the new `pandas`/`pydantic` deps land automatically on reinstall):

```console
conda activate pypeit14
cd /home/xavier/Projects/PypeIt/PypeIt
pip install -e ".[dev]"      # registers the `pypeit_dashboard` command
```

**Normal use** — start it *from the directory where you will run the
reduction* (it watches the working dir for new `*_QA` / `*_Science` /
`*_Calibrations` output folders):

```console
cd /path/to/your/RDXDIR        # e.g. a fresh work dir
pypeit_dashboard               # opens the Qt window
```

If the entry point isn't installed yet, the equivalent direct invocation is:

```console
python -c "from pypeit.scripts.pypeit_dashboard import RunDashboard; \
           RunDashboard.entry_point()"
```

**Workflow inside the window:**

1. **Import Setup** → pick your `.pypeit` file. The *Setup File* and *Science
   File* fields populate (this no longer hangs).
2. **Check Status** → fills the **Status** tab with the per-calibration table
   (needs a setup loaded first).
3. **Run All** → runs the full reduction in a background process. Watch the
   **Logs** tab stream output; the **status bar** (Calibration ID / Detector /
   Step / Calibration Step) now updates live as each calibration step starts,
   and the QA / Calibrations / Science file-tree tabs populate as output
   directories appear. Double-click any file to open it.

**Testing tip (headless):** for the dev suite's `shane_kast_blue/600_4310_d55`
data, you can drive everything offscreen with
`QT_QPA_PLATFORM=offscreen`; the lingering `pypeitdev/dashboard/`
`test_step_wiring.py` shows the pattern for exercising the status bar without a
full reduction.
