# Develop Stage 6 of the PypeIt Dashboard

## Goals

Continuing the staged build defined in `pypeit_dashboard_coding.md`
(*Developing → Build order*), this document guides **Stage 6 — Science frames**:
populate the **Science** section (a placeholder since Stage 2) so the Dashboard
shows, per reduced science/standard exposure, how far its reduction got and how
good it looks — the design's R15/R18.

The science **state layer is already done** (see
`claude_prompts/state_science.md`): `RunPypeItState` records a `science` list of
`ScienceFrameState` entries (one per `(frame, det)`) with the four macro-step
statuses (`process` → `findobj` → `skysub` → `extract`), the `spec2d`/`spec1d`
products, `nobj`, and per-slit / per-object detail; it is populated **live**
during a run and **derived from disk** when there is no state file. Stage 6 is
the **Qt view** over that data — the last build-order stage.

Stage 6 builds on what already exists:

- **Stage 1** — `DashboardModel` (loads/derives the state; the calib accessors
  `status_table`/`slit_table`/`step_metrics`; `is_stale`, `log_path`,
  `state_path`).
- **Stage 2** — the `StatusView` with its **placeholder Science section** and the
  status palette + glyph encoding to reuse.
- **Stage 3** — the `CalibrationsView` drill-down pattern (scope selectors,
  detail panel, per-slit table) and the `Launcher` (subprocess inspection).
- **Stage 5** — live monitoring (`RunLock.stateChanged` →
  `MainWindow._refresh_from_state`) and the two-channel `ActivityBar`; a
  model-driven Science view auto-refreshes for free.

The implemented state API the view consumes (in the **`pypeit/state/`** package):
`RunPypeItState.get_science_status()` → a per-frame DataFrame with columns
**`frame`, `detector`, `objtype`, `process`, `findobj`, `skysub`, `extract`,
`nobj`, `spec2d`, `spec1d`**; per-frame `ScienceFrameState.slits`
(`ScienceSlit`: status from `BADSKYSUB`/`BADEXTRACT`, `nobj`) and `.objects`
(`ScienceObj`: `snr_find`, `s2n`, `spat_pixpos`, `fwhm`, `sign`, `extracted`);
and `pypeit.state.science_status.derive_science_from_disk` for the no-state-file
case.

**Scope note (updated after the S6-Q answers).** Stage 6 **presents** science
state, launches the **existing** product viewers (per-object for 1D, S6-Q3), and
— per **S6-Q6** — adds a **(Re)Build** control mirroring the Calibrations one,
launching `pypeit_reduce_by_step` to (re)run a science step (`process` /
`findobj` / `extract`) for a frame/detector. (This is the science analogue of
the Stage 4 calib (Re)Build; the products are the `Intermediate/` files +
`spec2d`/`spec1d`.) Launching a **full `run_pypeit`** stays out of scope (it is
only *observed*); the `.log` tail view stays deferred; deferred science metrics
(`OPT_CHI2`, `WAVE_RMS`, flexure — `state_science.md` Q6) are not surfaced until
the state model carries them. *The science (Re)Build has open design points —
see S6-Q10–S6-Q12.*

Each stage below carries the design requirements it satisfies (the `R` items in
`pypeit_dashboard_design.md`), a concrete task breakdown, the files it touches,
and acceptance criteria. Open implementation choices are raised in the
**Clarifications** channel for the user to answer inline before coding begins.

### Stage 6 — Science frames

**Design refs:** R15 (the Science view — per-frame rows + per-slit/per-object
drill-down, reusing the palette R10 and the summary R7), R18 (an
equally-prominent, filterable/scrollable Science section), R8 (grouping). Builds
on the implemented `RunPypeItState.science` state layer.

**Goal.** Replace the Science placeholder with a real view that renders
`get_science_status()` — one row per `(frame, det)` with the four macro-step
statuses (color+glyph), `nobj`, and `spec2d`/`spec1d` presence, standards tagged
in the same table — plus a per-frame drill-down (per-slit + per-object tables)
and product-viewer launches, all reusing the Stage 3 patterns and the Stage 5
live-refresh.

**Mechanism** (S6-Q answers folded in; open science-(Re)Build points in
S6-Q10–S6-Q12):

1. **A third Science tab** (S6-Q1) — Status | Calibrations | **Science** — with a
   per-frame **table** + drill-down mirroring the Calibrations view; plus a
   **compact Science summary** in the Status view (counts only) and the summary
   strip extended to span science (S6-Q9).
2. **Model accessors** (Qt-free, mirroring the calib ones) — add to
   `DashboardModel`: `science_table()` (normalized `get_science_status`),
   `science_frame_entry(frame, det)`, `science_slit_table(frame, det)`,
   `science_object_table(frame, det)`; and **derive science on launch** when
   there is no state file via `derive_science_from_disk(run_state, redux_dir,
   fitstbl)` (S6-Q7).
3. **The per-frame table** — **flat rows** per `(frame, det)` (S6-Q4) with an
   explicit **`objtype` column** (science/standard, S6-Q5); the four macro-step
   statuses rendered as **palette color+glyph cells** (S6-Q6); `nobj` and
   `spec2d`/`spec1d` presence; filterable/scrollable (R18).
4. **Per-frame detail panel** (S6-Q2, mirrors Calibrations) — a per-slit
   `ScienceSlit` table (status from `BADSKYSUB`/`BADEXTRACT`, `nobj`) and a
   per-object `ScienceObj` table (snr_find, s2n, spat_pixpos, fwhm, sign,
   extracted); product/per-object viewers and the (Re)Build control below.
5. **Inspection viewers** — `inspect.py` gains `spec2d_command`
   (`pypeit_show_2dspec <spec2d> [--det]`) and a **per-object** `spec1d_command`
   that launches `pypeit_show_1dspec <spec1d> --obj <name>` for the selected
   object, **reconstructing the object name** (S6-Q10 option (a))
   `SPAT{round(spat_pixpos):04d}-SLIT{slitid:04d}-{detname}` from the
   `ScienceObj` (`spat_pixpos`, `slitid`) + the frame's `det` — matching
   `SpecObj.set_name` (e.g. `SPAT0424-SLIT0000-DET01`). Gated on the product
   existing; reported on the **Inspection** ActivityBar channel. *(Impl caveat:
   PypeIt names objects from `SPAT_PIXPOS_ID`; if a reconstructed name ever
   misses, fall back to `--list`.)*
6. **(Re)Build control** (S6-Q6, the science analogue of Stage 4) — per
   `(frame, det)` step, a blue (Re)Build that launches
   `pypeit_reduce_by_step <pf> <frame> <step> --det` (`step` ∈
   process/findobj/extract), governed by the **same `RunLock`** (single-run
   lock + live monitoring). Resolved: **(S6-Q11)** mirror the `run_to_calibstep`
   state-write fix — thread `run_state` through `reduce_by_step` (via the science
   recorders) + a final `derive_science_from_disk` write — so the science
   (Re)Build is observable/live; **(S6-Q12)** clobber = **re-run with a
   confirmation** naming the file(s) `reduce_by_step` will overwrite (no
   move-aside), and **enable a step only when its prerequisite product exists**
   (process always available; `findobj` needs the `process` product; `extract`
   needs the `findobj` product).
7. **Live refresh** — the view is model-driven, so Stage 5's
   `_refresh_from_state` re-renders it during a run with no extra wiring.

**Deliverables / tasks.** *(all S6-Q resolved)*

1. Model science accessors + science derive on launch (S6-Q7).
2. `inspect.py`: `spec2d_command`, per-object `spec1d_command` (reconstructed
   `--obj`, S6-Q10), and `science_run_command` (`pypeit_reduce_by_step`).
3. The `reduce_by_step` **state-write fix** (S6-Q11) — thread `run_state` through
   it (science recorders) + a final `derive_science_from_disk` write, mirroring
   the Stage-4 `run_to_calibstep` fix.
4. The Science tab (table + detail panel) + the Status-view compact summary,
   wired into the window + the live refresh.
5. The science **(Re)Build** control (S6-Q12): re-run with a file-naming
   confirmation, reuse the `RunLock`, enable a step only when its prerequisite
   product exists.
6. Summary-strip extension (R7, S6-Q9).
7. CI-safe `pytest-qt` tests over a synthesized science fixture + a science model
   fixture; harness renders + milestone screenshots. (The real
   `pypeit_reduce_by_step` (Re)Build is an interactive Sign off.)

**Acceptance criteria.** *(all S6-Q resolved)*

- The Science tab shows flat `(frame, det)` rows with an `objtype` column, the
  four step statuses (palette color+glyph), `nobj`, and `spec2d`/`spec1d`;
  scrollable; standards tagged.
- Selecting a frame shows its per-slit and per-object detail; "View spec2d"
  launches `pypeit_show_2dspec`, and a per-object "View 1D" launches
  `pypeit_show_1dspec` for the **selected object**.
- A (Re)Build relaunches the chosen science step (`pypeit_reduce_by_step`),
  governed by the run-lock, and the view updates (live + on completion).
- A launch with no state file still shows science derived from disk (S6-Q7).
- 0 objects reads as success; CI-safe tests pass offscreen; light/dark legible.

### 2026-06-16 (Round 4: planned science frames vanished after building calibrations)

**Task.** Twelfth task under *Prompts / Stage 6* — Round 4: planned science
frames disappear after a Dashboard calibration (re)build; investigate + fix.

**Root cause.** Planned science frames are seeded **in memory** by the
Dashboard's derive path only (the Dashboard never writes state). A calibration
(Re)Build runs `pypeit_run_to_calibstep`, which **writes `*_state.json` with
calibrations but no science**; the completion refresh
(`MainWindow._refresh_from_state`) reloads the model from that file
(`derive=False`), and the model's **load path did not seed planned science** — so
the Science view emptied out.

**Fix (`pypeit/dashboard/model.py` + `pypeit/state/science_status.py`).** Seed
planned science on the **load path** too. Refactored the seeder into
`planned_science_from_fitstbl` (compute the planned-frame list) +
`seed_planned_science_entries` (seed from that list); the model caches the list
per ``.pypeit`` (`_PLANNED_SCIENCE_CACHE`, warmed for free on derive) and
`_acquire_state` now calls `_seed_planned_science()` after **loading** a state
file as well. A cold-cache metadata build is gated on `allow_build=derive`, so it
happens at most once at launch — live-monitoring reloads and CI loads use the
warm cache (no heavy/repeated builds, no log noise).

**Verified.** `pytest test_dashboard.py + test_state.py` → **95 passed**
(+`test_planned_science_persists_on_state_load`). Real-data end-to-end on
`shane_kast_blue/830_3460_d46`: derive shows the planned frame + warms the cache;
writing a science-less state file (as the calib (re)build does) then reloading
with `derive=False` **re-shows** the planned frame (calib 0, `undone`, raw file
recorded). The Science view no longer empties after building calibrations.

### 2026-06-16 (Round 5: all (Re)Build buttons disabled after a science step-build)

**Task.** Thirteenth task under *Prompts / Stage 6* — Round 5: after building
calibrations then running `process` on the standard, **all** (Re)Build buttons
(standard + science) were disabled; investigate + fix.

**Root cause (mirror of Round 4).** The (Re)Build is gated on
`calibrations_ready(group, det)`. `pypeit_reduce_by_step` builds a **fresh**
`PypeIt` whose `run_state` has the calibrations only as the required (`undone`)
set — it loads the calib files to process the frame but never records them
`success`. Its final `run_state.write()` **overwrote `*_state.json`**, replacing
the `success` calibration statuses (from `pypeit_run_to_calibstep`) with
`undone`; the Dashboard reload then saw the calibrations as not-built →
`calibrations_ready` False → every science/standard (Re)Build disabled.

**Fix (`pypeit/state/run_state.py` + both step-runner scripts).** New
`RunPypeItState.merge_from_disk()` overlays the existing on-disk calibration +
science statuses onto a freshly-built state (matching `(calib_id, det)` /
`(frame, det)`; preserves `outfile`). `pypeit_reduce_by_step` and
`pypeit_run_to_calibstep` both call it right after building `PypeIt`, before they
write — so a science step-build keeps the calibrations (Round 5) and a
calibration build keeps the science (Round 4, now also fixed at the source). The
shared state file is no longer clobbered by the last writer.

**Verified.** `pytest test_dashboard.py + test_state.py` → **96 passed**
(+`test_merge_from_disk_preserves_other_portion`). State-level reproduction of
the exact sequence: calib build (calibs, no science) → `reduce_by_step`-style
write *with the merge* (records the standard's `process`) → Dashboard reload →
**calibrations present, `calibrations_ready=True`, standard recorded** → the
(Re)Build buttons are enabled again. Docs build clean (RTD-strict, 0 warnings).
