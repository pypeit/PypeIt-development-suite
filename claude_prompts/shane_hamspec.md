- Frame set: 2 pixflats (wide plate 800:6.0, flood — no orders), 2 blazeflats

  be distinguished by `PLATENAM`/`OBJECT`, unlike the current

### 2026-06-16 (Prep #2: ran pypeit_setup; found typing/config bugs)

Ran `pypeit_setup -s shane_hamspec -c all` on the 7-frame data set. It
completed (the Report-01 import fix is what lets the CLI run) but exposed four
bugs in `shane_hamspec.py`, documented in `Reports/02_pypeit_setup.md`:

1. **Over-split into 5 configs.** `configuration_keys` includes `decker` and
   `filter1`, which vary by design (wide vs narrow aperture plate; Open/BG12/
   BG13 blocking filters). `xdangle` (9194) and `binning` (1,1) are constant,
   so they alone give 1 config. The in-code comment even says decker should be
   excluded, but the code includes it. → set keys to `['xdangle','binning']`.
2. **Standard dropped.** d2100 (HD188209) typed `None` because the lamp-off
   test compares against lowercase `'off'` while the header is `LAMPPOS='Off'`
   (case mismatch). Fix: case-insensitive off-test. Secondary: at 300 s it
   would then type `science`, not `standard` (exprng collision).
3. **pixelflat vs trace not separated.** All `PolarQuartz` frames typed
   `pixelflat,illumflat,trace`; per Q&A the wide-plate (800:6.0) are pixelflats
   and narrow-plate (640:5.0) blazeflats are traceflats. Need PLATENAM routing.
4. **airmass=None.** No `AIRMASS` card in headers (warning only); can compute
   via compound_meta from RA/DEC+MJD+Shane location.

All four are Development-phase edits. New Q&A items 6–9 logged for JXP.

### 2026-06-17 (Prep #3: airmass via reusable astropy helper + verified setup)

JXP implemented Problems 1–3 (config keys → `['xdangle','binning']`,
`standardframe['exprng']=[1,301]`, plate-based flat typing). I implemented

What I did / learned:
- Added a **reusable** helper
  `pypeit.core.meta.airmass(ra, dec, obstime, longitude, latitude, elevation)`
  — builds an astropy `EarthLocation`, transforms the target `SkyCoord` to the
  local `AltAz` frame at `obstime`, returns `sec z` (NaN below horizon), per
  the astropy observation-planning example. Other spectrographs can reuse it.
- Wired it into `shane_hamspec.compound_meta` (no `AIRMASS` card exists), using
  the `ShaneTelescopePar` lon/lat/elevation. Verified: calibrations ≈1.0000
  (parked at zenith, DEC ≈ Lick latitude), HD188209 = 1.2394 (realistic).
- **Two follow-on bugs** in the new typing code blocked setup; fixed both
  (Q&A 10–11): `fitstbl['PLATENAM']` → `fitstbl['decker']` (table is keyed by
  PypeIt meta name, not raw card), and made `lamps()` off-test
  case-insensitive (it was called with `'Off'` but only handled `'off'`).
- `pypeit_setup -c all` now exits 0 with **1 configuration** and all frames
  typed correctly: arcs (d2084/85), trace+illumflat from the narrow plate
  (d2090/95, confirms Q9), pixelflat from the wide plate (d2000/40), and
  HD188209 as the on-sky frame.
- **Residual (Q&A 12):** HD188209 (300 s) types as `science`, not `standard`,
  because it falls in both exprng windows; setup "chooses the most likely"
  (science). Needs disambiguation for the standard.
