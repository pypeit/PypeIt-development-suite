### Q&A

Questions from Prompt 1 (2026-10-11; details in Report 03).

**1. Standard-star typing.**  Every KOA frame, including the A0V stars
   and the darks, has `OBSTYPE = 'a'`, so the design rule
   `standard = OBSTYPE 's'` never fires.  I type a frame `standard` when
   its target name carries a spectral-type tag (`HD101060(A0V)`) or is
   a bright-star catalogue name (HD, HIP, HR, BD, ...) with exptime
   <= 60 s; science and standard are exclusive.

   *Recommendation: keep this heuristic and let users fix the rare
   misfire (e.g. a long HR 8799 sequence would still be science; a
   short one would be typed standard) in the pypeit file.*  Why: no
   header card distinguishes the stars (`KOAIMTYP = 'object'` for both),
   and the names Keck observers use for telluric stars follow these
   patterns.  OK?
>A. Ok

**2. ITIME vs TRUITIME.**  The 2024 headers carry `TRUITIME` (absent
   in 2015/2016), and it differs from `ITIME` for short frames: 1.475 s
   vs 2 s, 2.95 vs 3, 8.851 vs 10, 598.96 vs 600.  The DN conversion
   currently uses `ITIME x COADDS` (Q&A 12).

   *Recommendation: use `TRUITIME x COADDS` when `TRUITIME` is present,
   `ITIME` otherwise.*  Why: `SCI` is a ramp slope per second, so the
   counts actually collected are slope x effective integration time;
   with `ITIME` the 2-s standards are over-counted by 36 %, which
   biases PypeIt's Poisson noise (not the fluxing, as long as the same
   exptime is used throughout).  Shall I switch?

>A. Yes, switch

**3. Sky frames in the pypeit files.**  `pypeit_setup` types `ISSKY=1`
   frames `science,sky` (design 4.3).  In the dev-suite files I removed
   `science` from them (NGC 3245 skies: `arc,sky,tilt,trace`; standard
   skies: `sky`) so they are only used as backgrounds and not reduced
   by themselves.

   *Recommendation: keep it so, and document it in M5.*  Why: one sky
   serves two objects; reducing it as a science frame would double the
   run time for no product.  OK?

>A. Ok

**4. `specflip = True`.**  The Keck coefficients put long wavelengths
   at low column numbers, so I set `specflip = True` (design: False)
   to follow PypeIt's "wavelength increases with pixel" rule.  This
   means the M3 `rectify` step (after `orient`) must transpose and flip
   the matrix.

   *Recommendation: keep `specflip = True`.*  Why: downstream PypeIt
   code (wavelength fitting, sensfunc, coadds) assumes increasing
   wavelength; it is cheaper to flip the matrix once.  OK?

>A. Ok
