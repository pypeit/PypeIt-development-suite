# Keck/OSIRIS milestone M4: science-mode reduction of NGC 3245 (Kbb/050)

## Goals

Reduce the KOA 2024-02-03 Kbb/050 set end to end: A-B and OH-scaled sky subtraction,
OH wavelength refinement, datacube through a generic fiber-cube script, and telluric
correction with the A0V standards.  Requires the Kbb/050 rectification matrix from Keck
in `RAW_DATA/keck_osiris/Kbb_050/calib/`.

## Tasks

1. Confirm the matrix is present; if not, stop and say so in Q&A.
2. A-B / A-sky through `bkg_id` with no dark subtraction (Q&A 23);
   darks only for unpaired frames, grouped by ITIME.
3. Davies (2007) OH-scaled sky subtraction: `osiris_oh_scaling` option
   in `SkySubPar` (`add-parameter`); implementation in
   `pypeit/core/skysub.py` (group OH lines, fit per-group scale factors
   between science and sky spectra per lenslet or per block, apply
   before subtraction); call it from `FiberFindObjects` when set.
4. OH wavelength refinement: an OSIRIS OH line list in
   `pypeit/data/arc_lines/lists/`, `reference = 'sky'`, per-lenslet
   zero-point correction (or a per-block linear term) with a QA plot
   of the shift statistics; keep the Keck solution where fewer than 3
   lines are usable.  Then re-run the OH-line tilt test
   (`vet_tests/test_keck_osiris_flow.py`) on the refined solution and
   remove the `xfail`: this closes the M3 criterion (slope < 0.05 px
   over a block; M3 Q&A 1, design decision M3-1).
5. Generic `pypeit_fiber_cube` script (`new-script`) on
   `core/datacube.build_cube_from_spec1d` and the spectrograph's fiber
   hooks; make `pypeit_binospec_ifu_cube` a thin alias (Q&A 24).  Build
   the NGC 3245 cube with the lenslet grid, SSCALE and position-angle
   WCS.
6. Telluric correction and flux calibration with HD101060 using
   PypeIt's IR sensfunc/telluric tools; check the K-band telluric grid.
7. Dev suite: `keck_osiris/Kbb_050` reduce test, telluric test, vet
   tests (cube structure, OH-line tilt test on an ISSKY=1 frame).
8. Keck-derived fixed tilts (M3 Q&A 2, design 5.4): make
   `KeckOSIRISSpectrograph.get_fixed_tilts` return a `WaveTilts` with a
   2D Legendre per block reproducing the 1.92 px per lenslet-row
   stagger (target 0.02-0.03 px rms against the Keck coefficients), and
   reduce the `get_fiber_wavelengths` per-lenslet offsets to the
   residual, so the spec2d wavelength image is exact.  Do this before
   task 3 if the Davies scaling is applied on the 2D rectified frame.
   Add a unit test comparing the tilt-based wavelength image with the
   per-lenslet Keck solutions.
9. `DTMP7` re-test (M3 Q&A 4): on the 2024 Kbb/050 frames measure the
   OH-line offset against the vacuum list with and without the
   grating-temperature term (on 2016 Hn3 it is +0.40 A with, -0.01 A
   without).  If it also degrades the 2024 data, add a parameter to
   switch it off (`add-parameter`) or let the OH refinement absorb it;
   record the decision in the report and the design document.
10. Context from M3 you must respect (design decisions M3-1 to M3-7):
   one spec1d spectrum per lenslet via the lenslet image (3040 for
   narrowband Hn3); `osiris_rect_method = 'lstsq'` is the default;
   reference rows and L.A.Cosmic run per raw frame; the cube script
   must call `set_lenslet_state` before using the fiber hooks.
11. Matrix selection by validity epoch (do this first; it blocks
   everything on Kbb_050).  The Kbb/050 matrix in `Kbb_050/calib/` is
   dated 2024-05-24, *after* the 2024-02-03 observations, yet it is the
   right one: Keck builds one matrix per *validity epoch* and the file
   date is merely when the calibration scan was taken.  The M2 rule in
   `lenslet_rectify.select_matrix` ("latest matrix dated on or before
   MJD-OBS") therefore raises `PypeItError` on this file.  Replace it
   with epoch-window selection: ship a small table
   `pypeit/data/spectrographs/keck_osiris/rectmat_epochs.ecsv` with the
   validity windows from http://tkserver.keck.hawaii.edu/osiris/ (UT start/end,
   YYMMDD; the current list is 050530-060207, 060208-081207,
   091004-120102, 120103-121108, 121109-151231, 160101-170131,
   170201-171105, 171106-180106, 180107-180920, 181021-200110,
   200111-201106, 201217-220904, 221010-230520, 230701-250310,
   250414-260421, 260422-260603, 260604-open; note the gaps between
   epochs), pick the epoch containing MJD-OBS (nearest epoch with a
   warning if the date falls in a gap), and among the matrices in the
   directory for that filter/scale prefer one whose file date lies
   inside the epoch; fall back to the old latest-before rule only when
   no matrix lies inside the epoch, with a warning.  Also accept
   `.fits.gz` files (tkserver serves them gzipped) in
   `parse_matrix_filename`/`RectMatrix`.  Add unit tests (the
   2024-02-03 / 2024-05-24 case must select; a 2016 Hn3 frame must
   still select `s160318_c005`).  Record the tkserver URL and the
   epoch rule in design Section 7 and in the M5 user documentation
   task.
